# outer-joins-ministore
•	¿Por qué usaste LEFT JOIN para la Consulta 1 y no INNER JOIN? ¿Qué se perdería si usaras INNER JOIN?
Use  LEFT JOIN porque la tabla productos está ubicada a la izquierda del JOIN y necesitamos conservar todos sus registros, tengan o no una venta asociada. Cuando un producto no tiene coincidencia en la tabla ventas, SQL igualmente devuelve el producto y completa las columnas correspondientes a ventas con valores NULL. En este caso, los productos con producto_id 108 y 109 no tienen ventas registradas, por lo que aparecen con NULL en las columnas provenientes de la tabla ventas. Si utilizáramos un INNER JOIN, esos productos no aparecerían, porque este tipo de JOIN solamente devuelve registros que tienen coincidencia en ambas tablas.

•	¿Por qué usaste RIGHT JOIN para la Consulta 2? ¿Qué tabla está a la izquierda y cuál a la derecha en tu consulta?
Use RIGHT JOIN porque queremos conservar todos los registros de la tabla ventas, que se encuentra del lado derecho del JOIN. De esta forma, incluso si una venta tiene un producto_id que no existe en la tabla productos, la venta sigue apareciendo en el resultado. En los datos de prueba existe una venta con producto_id = 999. Ese producto no existe en el catálogo, por lo que las columnas correspondientes a productos aparecen con valor NULL. Esto permite identificar posibles errores de carga o inconsistencias entre las ventas registradas y el catálogo de productos.
•	¿Qué representan los valores NULL en cada resultado? Explicá con un ejemplo concreto de los datos qué significa que venta_id sea NULL en la Consulta 1 y que producto_id de productos sea NULL en la Consulta 2.
En un OUTER JOIN, un valor NULL indica que no se encontró una fila relacionada en la otra tabla. Por ejemplo, en el LEFT JOIN, si venta_id aparece como NULL, significa que ese producto existe en el catálogo pero nunca tuvo una venta asociada. En cambio, en el RIGHT JOIN, si las columnas del producto aparecen como NULL, significa que existe una venta cuyo producto_id no tiene coincidencia en la tabla productos. Por lo tanto, en este ejercicio los NULL son útiles porque permiten detectar registros sin correspondencia entre las tablas.

•	¿Cuándo usarías FULL OUTER JOIN en un caso real de negocio?
Un FULL OUTER JOIN sería útil en un proceso de auditoría o conciliación entre dos fuentes de información.
Por ejemplo, una empresa podría comparar datos de un sistema de ventas con los datos de un sistema de inventario. El FULL OUTER JOIN permitiría visualizar tanto los registros que coinciden entre ambos sistemas como aquellos que existen únicamente en uno de ellos. En este ejercicio permite detectar al mismo tiempo productos que nunca fueron vendidos y ventas registradas con productos inexistentes. Esto facilita la identificación de inconsistencias, errores de carga y problemas de integridad de datos.
